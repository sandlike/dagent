# 前端设计文档：OpenCode 容器管理平台

> 版本：v0.1 | 日期：2026-06-28 | 面向：UI 设计师 / 前端开发
> 技术栈：Vue 3 + 组件库（建议 Element Plus 或 Naive UI）+ Tailwind CSS
> 配套 PRD：`../PRD.md` v0.3

---

## 1. 产品总览

### 1.1 一句话定位

一个让用户**配置 → 部署 → 对话 → 管理** 自己的 OpenCode agent 实例的 Web 平台。

### 1.2 核心用户旅程

```
注册/登录 → [新建实例：配置向导] → 一键部署
          → [实例列表] → 进入实例
                         ├─ 对话（与自己的 agent 聊天）
                         ├─ Skill 管理（增删 skill，实时生效）
                         └─ 监控（健康/会话/状态）
```

### 1.3 六大功能区

| # | 模块 | 一句话 |
|---|------|--------|
| 1 | 账号 | 注册 / 登录 / 退出 |
| 2 | 实例列表 | 用户所有 OpenCode 实例的总览与管理 |
| 3 | 配置向导 | 四步引导生成 opencode.json 并部署 |
| 4 | 内嵌对话 | 在平台内与实例对话 |
| 5 | Skill 管理 | 管理实例的 skill（zip 上传/删除，实时生效） |
| 6 | 运行时监控 | 查看实例健康、会话、状态 |

---

## 2. 设计原则

| 原则 | 说明 |
|------|------|
| **开发者审美** | 目标用户是技术人员，偏好信息密度高、去装饰、克制配色的界面（参考 Vercel / Linear / GitHub） |
| **配置即所见** | 配置向导左侧填表，右侧实时 JSON 预览，让用户始终知道"我配的东西最终长什么样" |
| **状态始终可见** | 实例状态（部署中/运行中/异常）用颜色 + 文字双重表达，全平台统一 |
| ** destructive 操作二次确认** | 删除实例、删除 skill、重启等必须二次确认 |
| **响应式** | 主桌面端（≥1280px），平板（768-1280）可用，手机仅保留只读列表 |
| **暗色模式优先** | 开发者工具调性，建议先出暗色稿，亮色作为可选 |

## 3. 信息架构与导航

### 3.1 全局布局

```
┌─────────────────────────────────────────────────────────┐
│ 顶栏：Logo  │  实例列表  对话  ...(导航)  │ 用户菜单 ▾   │  ← 56px
├──────────┬────────────────────────────────────────────┤
│          │                                            │
│  侧边栏   │            主内容区                          │
│ (实例切换)│                                            │
│  200px   │                                            │
│          │                                            │
└──────────┴────────────────────────────────────────────┘
```

- **顶栏（全局）**：左侧 Logo + 主导航；右侧用户头像菜单（用户名、退出）。
- **侧边栏（实例内）**：进入某个实例后出现，顶部是实例切换器（下拉选其它实例），下方是该实例的子导航（对话 / Skill / 监控 / 设置）。
- **未选实例时**：侧边栏隐藏，主内容区显示实例列表。

### 3.2 路由结构

```
/login                          注册/登录（无布局壳）
/                               实例列表（首页）
/instances/new                  配置向导（全屏，无侧边栏）
/instances/:id                  → 默认重定向到 /instances/:id/chat
/instances/:id/chat             内嵌对话
/instances/:id/skills           Skill 管理
/instances/:id/monitor          运行时监控
/instances/:id/settings         实例设置（重启/删除/改配置）
```

### 4.3 配置向导 `/instances/new`（核心页）

全屏向导，左侧分步配置，右侧实时预览。

```
┌─────────────────────────────────────────────────────────┐
│  ← 返回实例列表          新建实例         实例名: [____]  │
├──────────────────────────────┬──────────────────────────┤
│  步骤导航 (左, 约 55%)        │  实时预览 (右, 约 45%)    │
│                              │                          │
│  ① 基本信息 ✓                │  ┌─ opencode.json ────┐  │
│  ② 模型与 Provider           │  │ {                  │  │
│  ③ 权限策略                   │  │   "provider": {    │  │
│  ④ MCP + Skills              │  │     "deepseek": {  │  │
│                              │  │       "options": { │  │
│  ━━━━━━━━━━━━━━━━━━━━━━━━   │  │         "apiKey":  │  │
│  当前步骤内容区               │  │         "{env:…}"  │  │
│  （见下方各步骤细节）          │  │       }            │  │
│                              │  │     }              │  │
│                              │  │   },               │  │
│                              │  │   "model": "…"     │  │
│                              │  │ }                  │  │
│                              │  └────────────────────┘  │
│                              │  [切换原始编辑] [导入JSON]│
│                              │                          │
│                              │  ── 部署清单 ──           │
│                              │  ✅ ConfigMap            │
│                              │  🔒 Secret (apiKey,密码) │
│                              │  📦 Deployment           │
│                              │  📂 PVC (.opencode/)     │
│                              │                          │
│  [← 上一步]        [下一步 →]│  [    一键部署    ]      │
└──────────────────────────────┴──────────────────────────┘
```

向导统一规范：
- 顶部步骤导航，已完成显示 ✓，当前高亮，未到达置灰。
- 右侧预览区**随左侧输入实时更新**（无需点确认）。
- `[导入JSON]`：弹出文件/文本框，粘贴 opencode.json，解析后**反向回填**左侧各步骤（D2 决策）。
- `[切换原始编辑]`：预览区变为可编辑文本框，高级用户直接改 JSON。
- `[一键部署]`：最后一步才启用；点击后跳转到实例列表，新卡片显示"部署中"。

#### 步骤 ① 基本信息

```
  实例名称 *                    [ my-coder____________ ]
  显示描述                      [ 一个用于日常编码的助手___ ]
  默认 Agent                    (•) build   ( ) plan
  K8s Namespace                 [ opencode-users ] (默认，可改)
```

#### 步骤 ② 模型与 Provider

```
  Provider 模板                 [ DeepSeek ▾ ]   ← 下拉，含常见模板
                                 内置: DeepSeek / Anthropic / OpenAI /
                                       Bedrock / Azure / 自定义(OpenAI兼容)

  ── DeepSeek 配置 ──

  API Key *                     [ sk-******** ]  🔒 将写入 Secret
                                 提示: 用 {env:DEEPSEEK_API_KEY} 占位
  Base URL                      [ https://api.deepseek.com/v1 ]
  Timeout (ms)                  [ 300000 ]

  主模型 *  [ deepseek/deepseek-v4-flash ▾ ]
  小模型    [ deepseek/deepseek-chat ▾ ]   (用于标题生成等)
```

要点：
- API Key 输入框旁有锁图标 🔒，明确告知"将写入 Secret，不进 ConfigMap"。
- 选 Provider 模板后，baseURL/timeout 自动填默认值，模型下拉自动填充该 provider 的常见模型。
- 选"自定义(OpenAI兼容)"时，展开额外字段：npm 包名、baseURL、自定义 models 列表。

#### 步骤 ③ 权限策略

```
  权限模式
  ┌─────────────────────────────────────────┐
  │ ( ) 只读      edit/bash = deny          │  ← 预设
  │ (•) 审批制    所有操作 ask              │
  │ ( ) 全开      默认 allow                │
  │ ( ) 自定义    ↓ 下方表格配置            │
  └─────────────────────────────────────────┘

  （选"自定义"时展开工具×动作表格）

  工具权限表                    动作
  工具          │  allow  │  ask  │  deny  │
  ──────────────┼─────────┼───────┼────────┤
  read  (读文件) │   ●     │       │        │
  edit  (写文件) │         │   ●   │        │
  bash  (shell)  │         │       │   ●    │
  grep (搜内容)  │   ●     │       │        │
  glob (搜文件)  │   ●     │       │        │
  webfetch      │         │       │   ●    │
  skill         │   ●     │       │        │
  task (子agent)│         │   ●   │        │

  ▸ bash 细粒度规则 (展开)        ← glob 规则行
    git status *   →  allow    [✕]
    npm test*      →  allow    [✕]
    rm -rf *       →  deny     [✕]
    [ + 添加规则 ]
```

要点：
- 选预设模式时表格只读展示（让用户看见预设的含义）；选自定义才可编辑。
- bash 规则区折叠，展开后是 `命令模式 → 动作` 的行列表，可增删。
- 这一步直接驱动生成 `permission` 对象。

#### 步骤 ④ MCP + Skills

```
  ── MCP 服务器 ──                              [ + 添加 MCP ]

  ┌─ filesystem ────────────────────────────┐
  │ 类型  (•) local   ( ) remote            │
  │ command  [ npx -y @modelcontextprotocol │
  │            /server-filesystem /data ]    │
  │ cwd      [ /workspace           ]        │
  │ 环境变量  [ + 添加 ]                      │
  │                                  [删除]  │
  └─────────────────────────────────────────┘

  ┌─ github (remote) ───────────────────────┐
  │ 类型  ( ) local   (•) remote            │
  │ url     [ https://api.github.com/mcp ]  │
  │ headers [ Authorization: Bearer *** ]   │
  │ ▸ OAuth 配置 (折叠)                      │
  │                                  [删除]  │
  └─────────────────────────────────────────┘

  内置模板：[+filesystem] [+github] [+postgres]  ← 一键填充

  ── Skills ──

  额外 Skill 路径                [ + 添加路径 ]
  Skill URL                      [ + 添加 URL ]

  Skill 权限规则
    internal-*   →  deny     [✕]
    experimental-* → ask     [✕]
    [ + 添加规则 ]

  预置 Skill（部署时写入 PVC）
```

要点：
- MCP 卡片式，每个 server 一张卡，local/remote 切换改变表单字段。
- Skill 上传支持 zip（Q6 决策），上传后显示文件数，部署时解压到 PVC。
- 这一步的 skill 是**部署时预置**；运行时还可通过 Skill 管理页增删（实时生效）。

```
│          │                                              │
│ ◉ 对话    │  ┌─ 会话列表(左) ──┐  ┌─ 消息区(右) ─────┐  │
│ ○ Skills │  │ + 新建会话       │  │                  │  │

│          │  │   2 条消息       │  │  agent: 你好!...  │  │
```

要点：
- 左侧会话列表来自 `GET /session`（标题、消息数、时间）。
- 右侧消息区：用户消息靠右，agent 回复靠左，tool 调用折叠显示。
- 发送走 `POST /session/:id/message`（同步）或 `/prompt_async`（异步）。
- 回复通过 `GET /event` SSE 流式展示（打字机效果）。
- 状态标识：会话列表项前圆点表示状态（● 运行中 / ○ 空闲）。
- agent 正在响应时，输入框禁用 + "停止" 按钮替代发送。

要点：
- 每个 skill 一张卡片：名称、description（来自 SKILL.md frontmatter）、文件数、大小、更新时间。

- `[删除]`：二次确认，确认后调用监控服务 sidecar 删 PVC 目录，**立即生效**。
- `[下载]`：打包当前 skill 目录为 zip 下载。
- 上传/删除后，列表自动刷新（轮询或 SSE）。
- 顶部提示"实时生效，无需重启"——强调这是相对配置 JSON 的优势。

- 会话状态分布来自 `/session/status`。
- "最近会话"表格来自 `/session`（标题、状态、消息数、时间），点行可跳到对话页该会话。
- 扩展状态：MCP/Agent/Provider 来自 `/mcp`、`/agent`、`/provider`（附加信息）。
- Pod 日志折叠区：流式显示容器日志（可选功能）。
- 数据通过 SSE（`/event`）实时刷新，无需手动刷新。
- **无 Token 用量**（Q8 决策：API 不提供）。

## 5. 关键交互流程

### 5.1 新建实例全流程

```
实例列表 → 点[+新建实例]
  → 配置向导 步骤① → 填基本信息
  → 步骤② → 选 provider + 填 key
  → 步骤③ → 选权限模式
  → 步骤④ → 加 MCP + skill
  → 点[一键部署]
    → 后端写 ConfigMap + Secret + 创建 Deployment
    → 前端跳回实例列表，新卡片显示【部署中】
    → 轮询/SSE 等待 Pod 就绪 → 卡片变【运行中】
    → 点[进入] → 默认进对话页
```

### 5.2 从现有配置导入

```
配置向导任意步骤 → 点[导入JSON]
  → 弹窗：粘贴 opencode.json 或选文件
  → 前端解析 → 回填步骤①~④各字段
  → 用户检查/微调 → 继续[一键部署]
```

### 5.3 Skill 实时增删（核心卖点）

```
进入实例 → Skill 管理页
  → 拖拽 zip 上传 → 监控服务 sidecar 解压到 PVC
  → 列表立即出现新 skill（无需刷新/重启）
  → 下一次对话中 agent 即可调用该 skill

  → 点[删除] → 二次确认 → sidecar 删 PVC 目录
  → 列表立即移除 → agent 不再可用
```

### 5.4 对话流程

```
进入实例 → 对话页
  → 左侧选会话（或新建）→ 右侧加载历史消息
  → 输入框打字 → 点[发送]
  → POST /session/:id/message
  → SSE 流式接收 agent 回复 → 打字机展示
  → agent 调用 tool 时折叠显示 [tool: bash] [tool: edit]
  → 完成后输入框恢复可用
```

## 6. 状态规范（全平台统一）

### 6.1 实例状态

| 状态 | 含义 | 颜色 | 圆点 | 可进入 |
|------|------|------|------|--------|
| 部署中 | Pod 创建中 | 琥珀 amber | ○ 旋转 | 只读监控 |
| 运行中 | 健康 | 绿 green | ● | 全功能 |
| 异常 | health=false 或 Pod 失败 | 红 red | ● | 只读监控 |
| 已停止 | 用户手动暂停 | 灰 gray | ○ | 只读 |

### 6.2 会话状态（来自 `/session/status`）

| 状态 | 含义 | 颜色 |
|------|------|------|
| running | agent 正在响应 | 绿 |
| idle | 空闲 | 灰 |
| error | 出错 | 红 |

### 6.3 操作反馈

| 场景 | 反馈 |
|------|------|
| 短操作（上传/删除 skill） | Toast 提示（成功/失败） |
| 长操作（部署/重启） | 卡片内 loading + 进度文案 |
| 删除类操作 | Modal 二次确认；删实例需输入名称 |
| 网络错误 | 顶部红色 Banner + 重试按钮 |
| SSE 断连 | 监控/对话页顶部"重连中…"提示条 |

## 7. 组件库与视觉建议

### 7.1 推荐技术搭配

| 项 | 建议 |
|----|------|
| 框架 | Vue 3 + Composition API + TypeScript |
| 组件库 | **Element Plus** 或 **Naive UI**（都支持暗色） |
| 样式 | Tailwind CSS（与组件库配合做布局/间距） |
| 图标 | Lucide / Heroicons（线性风格，统一） |
| 图表 | 监控页用 ECharts 或轻量的 unplugin |

### 7.2 视觉风格关键词

- **Linear / Vercel / GitHub 风格**：克制、信息密度高、去多余装饰。
- 暗色为主：背景 `#0D1117`（类 GitHub dark）或 `#000000` + 卡片 `#161B22`。
- 亮色作为可选：背景 `#FFFFFF`，卡片 `#F6F8FA`。
- 强调色：品牌蓝或紫（如 `#3B82F6`），仅用于主按钮、链接、高亮。
- 状态色严格遵循第 6 节。
- 圆角：6-8px；间距：8 的倍数（8/16/24/32）。
- 字体：系统字体栈或 Inter；代码区用等宽（JetBrains Mono / Fira Code）。

### 7.3 配置向导预览区视觉重点

预览区的 JSON 是这个产品的差异化亮点，建议：
- 用等宽字体 + 语法高亮（key、string、注释不同色）。
- 用户在左侧改某字段时，右侧对应 JSON 行**高亮闪烁**一下，建立"我改的就是这里"的映射。
- JSONC 支持注释（opencode.jsonc 允许注释）。

## 8. 数据来源对照（给前端开发）

| 页面/功能 | API | 来源 |
|----------|-----|------|
| 实例列表 | `GET /api/instances`（管理平面后端聚合 K8s） | 管理平面后端 |
| 配置向导部署 | `POST /api/deploy` | 管理平面后端 → K8s |
| 对话-会话列表 | `GET /session` | 经后端代理 → opencode 实例 |
| 对话-发消息 | `POST /session/:id/message` | 同上 |
| 对话-流式回复 | `GET /event` (SSE) | 同上 |
| Skill 列表 | `GET /skills` | 经后端 → 监控服务 sidecar |
| Skill 上传 | `POST /skills/{name}` (zip) | 同上 |
| Skill 删除 | `DELETE /skills/{name}` | 同上 |
| 监控-健康 | `GET /global/health` | 经后端 → opencode 实例 |
| 监控-会话 | `GET /session` + `/session/status` | 同上 |
| 监控-实时 | `GET /event` (SSE) | 同上 |
| 监控-MCP/Agent | `GET /mcp` `/agent` `/provider` | 同上 |

> 所有对实例的请求都经管理平面后端代理，后端负责校验"该实例属于当前用户"（owner label 鉴权）。

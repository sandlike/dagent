# Grounded Development Plan

1. Read the confirmed requirement and every clarification round.
2. Inspect each real file before citing it.
3. Separate goals, non-goals, affected modules, interfaces, data changes, and implementation steps.
4. Include risks, mitigations, rollback, focused tests, and an acceptance checklist.
5. Keep the Workspace read-only and follow the caller's exact JSON schema.
6. Never invent paths, dependencies, commands, or results.
